# 태그 비트마스크 읽기 모델 전환 — A/B 실행계획 비교

날짜: 2026-08-11 · 캠페인: [`2026-08-11_tag-bitmask-read-model`](../../load-test/campaigns/2026-08-11_tag-bitmask-read-model/) (다섯 항목·시나리오별 판정 목적·반증 시나리오 사전 등록)
형상: **A** = V33 스키마 + EXISTS 태그 필터 + 옵티마이저 자연 선택(조건부 힌트 철회 상태의 SQL과 바이트 동일, 마이그레이션 적용 **전** 선채취) · **B** = V34(`place_stats`에 `created_at`·`tag_bitmask` + 커버링 인덱스 2개) + 마스크 술어
그리드: 지역 3(동네 1곳 100 / 4곳 400 / 시 단위 18곳 1,800) × 태그 7 × 정렬 2 + 핫패스 커서 2페이지 = 46칸, 칸당 `EXPLAIN ANALYZE` 3회 중앙값(경계 칸 7회)

## 2. B의 플랜 형태 — 46칸이 한 모양이다

B 트리 59개(그리드 46 + 재측정 13)에 등장한 노드 종류의 전수 집계:

```text
Limit · Filter · Sort · Index range scan on ps · Covering index lookup on ps   ← 이것이 전부
Nested loop / hash join / FirstMatch / Materialize / Single-row lookup         ← 0회
```

지역이 1곳이면 Sort가 빠지고(인덱스 순서로 충분) 여러 곳이면 붙는 차이만 있는데, 이는 A의
무태그 칸이 이미 갖던 성질이고 태그와 무관하다. 태그 규모(0~1,146)·지역 크기(100~1,800)·
정렬 축·페이지 번호 어느 것도 플랜 형태를 바꾸지 못했다.

동네 1곳의 조기 종료: 11건이 차는 칸은 주도 노드가 11~96행에서 멈췄다(무태그 11, 카페 72,
비인기 96 등). 후보 100을 끝까지 읽은 칸은 전부 매치가 11건 미만(핫패스 10, 희귀 조합 6,
합성 1, 0건 0)이라 전수가 곧 상한이다.

## 3. 핫패스 (S3) — 시 단위 + 카페 + 옵션 2그룹

| 칸 | A(자연) | 힌트 실측(기록 참조) | B |
|---|---:|---:|---:|
| 인기순 1페이지 | 2.05 | 1.03 | **0.509** |
| 인기순 2페이지 | 1.88 | (미측정이던 칸) | **0.624** |
| 최신순 1페이지 | 2.40 | 0.889 | **0.600** |
| 최신순 2페이지 | 1.89 | (미측정이던 칸) | **0.547** |

`JOIN_PREFIX`+`SEMIJOIN(FIRSTMATCH)` 두 힌트가 겨우 도달했던 자리를, 힌트도 판단 정책도
없이 그 절반 시간으로 지나간다. 직전 캠페인이 남겼던 "커서 2페이지 미측정" 구멍도 함께 메웠다.

## 4. 수용한 후퇴 (S2) — 상한이 지역 크기에 묶였다

시 단위 후퇴 칸 (사전 합의: A가 태그 주도로 잘하던 입력이 지역 전수 스캔이 되는 것을 수용):

| 칸 | A(자연) | B | 상대 |
|---|---:|---:|---|
| 비인기 메인(985) | 1.12 / 1.53 | 0.707 / 0.629 | 오히려 개선 |
| 메인+희귀 서브(min 185) | 0.469 / 0.840 | 0.598 / 0.649 | 소폭 후퇴 |
| 합성 규모 20 | 0.074 / 0.069 | 0.693 / 0.601 | 9배 후퇴, 절대 0.7ms |
| 0건 태그 | 0.019 / 0.013 | 0.720 / 0.558 | 39배 후퇴, 절대 0.72ms |

주목할 것은 B 열이 매치 수와 무관하게 **0.56~0.72ms 한 대역**이라는 점 — 무태그 시 단위
(0.715/0.708ms)와 같은 대역이다. "태그 필터가 붙어도 비용이 태그 없는 조회와 같다"가 표로
확인된 것이고, 이 결정론적 상한이 상대 39배라는 숫자보다 중요한 성질이다. 등록해 둔 대로
후퇴 칸의 요청 빈도가 낮으리라는 것은 **(추정)**이며 채택의 보조 근거로만 쓴다.

## 5. A의 부수 발견 — 흔들림은 등록 예상보다 넓었다

등록 시점에는 A의 플랜 플립을 "시 단위 + 태그" 문제로 알고 있었다. A 채취가 그 지도를 넓혔다:

1. **후보 400에서 이미 플립한다** — 동네 4곳 최신순 핫패스가 태그 주도(전국 1,146 엔트리
   전수)로 실행돼 인기순 같은 칸의 5.4배(1.57 vs 0.29ms). 직전 캠페인들이 지역 100/1,800
   두 점만 재서 못 본 자리다.
2. **페이지 번호로도 플립한다** — 같은 칸의 2페이지는 커서 술어가 붙자 지역 주도로 갈아타
   1.57 → 0.402ms. 판단 정책이 있었다면 "같은 요청의 1페이지와 2페이지가 다른 개입을
   요구한다"는 뜻이 된다.
3. **정렬 축으로도 플립한다** — 동네 1곳 + 희귀 서브 조합이 인기순은 지역 주도, 최신순은
   태그 주도(0.155 vs 0.298ms).

**최신순이 인기순보다 먼저 뒤집히는 기제도 트리에 남아 있다.** 무태그 최신순(town4)의 지역
주도 트리에서 표시용 `place_stats` LEFT JOIN의 추정이 `cost=221 rows=400`인데 실제 실행은
`loops=11`이다 — 정렬이 LIMIT으로 끊긴 뒤 11행에만 붙는 조인을, 비용 모델은 후보 400행
전부에 붙는 것으로 전액 계상한다(4장 맹점의 최신순 변형). 인기순은 V32 이후 이 조인 자체가
없어 같은 페널티가 없고, 그래서 같은 후보 400에서 인기순만 지역 주도를 유지했다. 추정
오차의 위치도 특정된다: town+active 필터 추정은 정확한 편(6.6% vs 실제 5.1%)이고, 큰 오차는
옵션 태그 IN 리스트 세미조인의 통과율(추정 0.0695 vs 실제 0.707, 10배 과소)이다.

B는 이 세 축 모두에서 형태가 갈리지 않는다(§2). 흔들림의 전모가 드러날수록 "판단할 거리를
없앤다"는 선택의 근거가 강해지는 구조라, 이 발견은 판정에는 안 쓰였지만 서사에는 중요하다.

## 6. 등록 문구의 한계 2건 (정직 기록)

- **S5 "A·B 플랜 노드 동일"은 최신순에 문면 그대로 적용할 수 없다.** A 최신순은 LEFT JOIN
  노드를 갖고 B는 그 조인 제거가 설계 목적이라 노드가 같을 수 없다. 등록 시점에 인기순만
  떠올리고 쓴 문구다. 판정은 취지(무태그 경로의 시간 동등 + 커버링 유지)로 했다 — 인기순은
  문면·취지 모두 충족, 최신순은 시간 동등(0.663→0.708 / 0.167→0.183 / 0.038→0.032ms).
- **무태그 A는 3회 측정뿐이라 B(7회)와 정밀 비교가 안 된다.** A는 마이그레이션 전 스키마에서만
  잴 수 있는데 스키마가 이미 넘어가 재측정 불가. town4·city18 최신순의 +7~10%는 인덱스 엔트리
  폭 증가(+8바이트)의 실비용일 수도, 3회 측정의 산포일 수도 있어 **구분 불가**로 남긴다.

## 7. 이 테스트로 말할 수 없는 것

- 실태그의 지리 편중 하의 거동 — 합성 태그는 전국 균등 분포다.
- 부하 하의 거동 — 부하를 걸지 않았다. 플랜이 단일 형태이므로 운영 회귀는 digest 실행당
  지표로 감시한다.
- "중간 규모 태그"의 후퇴 폭 — 벤치 실태그 MAIN이 985~1,146으로 촘촘해 중간 대역
  (200~900)은 실태그로 측정 불가였다. 합성 20과 985 사이는 보간이다.
- 태그별 요청 빈도 분포 — 미측정. 운영 지표 확보 후 확인 항목.
- "옛 구조 + 스펙(전부 포함) 구현" 형상 — 미측정 가설 형상이다. 처음 구조의 수치(11.3~22.3ms)는
  당시 실재한 구현(그룹 EXISTS + IN 리스트)의 실측이고, 전후 비교는 "같은 입력에 시스템이 쓴
  시간"의 비교로 유효하다. 비용의 지배 항(태그 주도 접근 경로의 읽기·프로브)이 결합 의미론과
  무관했고, 옛 구조에 스펙을 옳게 구현했다면 EXISTS가 늘어 같거나 더 나빴을 개연성이 높다 —
  단 이 마지막은 5장 실측(EXISTS 증가 시 세미조인 전략 흔들림)에 기댄 추정이지 실측이 아니다.

## 8. 재검토 조건

- **검색 엔진으로 넘어갈 기준**: NOT·수치 범위·반경 필터가 요구사항에 들어오거나, 태그의
  비트 자리가 62를 넘거나(1차 대응: 죽은 자리 재배치 → 2차: 마스크 컬럼 추가), 정렬 축이
  계속 늘어나는 시점. 그 전까지는 규모(장소 6,320·태그 34·최악 0.72ms)가 이관을 정당화하지
  않는다.
- 마스크 정합의 방어선은 두 겹이다 — 어드민 쓰기 경로의 동기 갱신(지연 0) + 매시 카운트
  배치의 재계산(드리프트 수명 ≤1h). 어느 한쪽 코드가 바뀌면 다른 쪽이 안전망임을 전제로
  검토할 것.

## 9-1. 추록 — 태그 필터 스펙 교정의 확인 채취 (같은 날 후속)

캠페인 판정 직후, 태그 필터의 제품 스펙이 **"설정한 태그를 전부 가진 장소만 조회"**로 확정됐다.
본 캠페인의 A·B는 당시 구현(그룹당 EXISTS + IN 리스트 / 그룹별 마스크 술어 3개)을 동치로
보존한 채 측정한 것이므로, 술어를 스펙대로 단일 마스크(`(tag_bitmask & :m) = :m`)로 교정하고
확인 채취를 별도로 받았다 (`bench/explain-b-and-confirm.sh`, 트리 `results/explain/b-and-*.txt`,
요약 `results/summary-b-and.csv`).

- **계획 형태 불변** — 14개 트리 전부 조인·세미조인 노드 0, 본 캠페인 B와 동일 구성
  (시 단위 Sort 있음 / 동네 Sort 없음)
- **대역 유지** — 시 단위 8칸 0.532~0.670ms, 본 캠페인 B 대역(0.509~0.720) 안. 극단 입력
  (옵션 11종 전부 요구, 데이터 구조상 매치 0)도 0.578~0.642ms
- **기준선 교차 일치** — 단일 태그(의미론 무관)의 매치 수(시 275·동네 17)와 주도 노드 실제
  행 수(72·61)가 본 캠페인 B와 정확히 일치
- **조기 종료 유지** — 매치 ≥11인 칸(동네+카페)에서 72·61행 멈춤. 매치가 11 미만으로 떨어진
  조합은 후보 전수가 상한(설계 그대로)
- 결과 검증은 IT로: 태그별 EXISTS 참조 구현과의 동치 + 목록·북마크 매처 교차 검증, 전체 221개
  통과. 술어를 `!= 0`으로 되돌리는 돌연변이에 IT 7건이 실패함을 확인(테스트 실효성)

본 캠페인의 다중 태그 칸(카페+옵션 그룹 IN 리스트)은 측정 당시 술어 기준의 기록으로 보존한다.
스펙 기준의 다중 태그 수치는 이 추록의 값을 정본으로 쓴다 — 시 단위 태그 2개 0.53~0.56ms ·
3개 0.55~0.67ms.
