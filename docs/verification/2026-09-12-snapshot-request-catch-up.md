# 스냅샷 요청 적재 대기 검증

2026-09-12, JDK 21 및 실제 MySQL Testcontainers 환경에서 구현 완료 후 검증했다.

## 전체 결과

`./gradlew clean build`가 2분 57초에 성공했다. `build/test-results/test/TEST-*.xml` 68개를 합산한 결과는 다음과 같다.

| 테스트 | 실패 | 오류 | 건너뜀 |
|---:|---:|---:|---:|
| 605 | 0 | 0 | 0 |

코디네이터가 빌드 로그의 성공과 XML 집계를 직접 확인했다. 이후 `./gradlew test --rerun-tasks`도 3분 20초에 성공했다. 기존 564개에 신규 적재 대기 검증과 삭제 표시값 회귀를 더한 결과다. 보고서 HTML은 `build/reports/tests/test/index.html`이며 빌드 산출물은 Git에 포함하지 않는다.

## 주요 검증

- `SnapshotLoadCoordinatorTest`: 요청과 설치 폴의 공유 적재, barrier/latch 경쟁, 실패·거절 뒤 재시도, 사본 취소의 비전파, 전용 적재 스레드.
- `PlaceListRequestOrchestratorTest`: 첫 페이지 발행 ID 비교, 로컬 일치 커서와 북마크 검색의 추가 head 조회 생략, 실제 만료와 적재 실패의 구분, 대기 시간 비연장, 재개 큐가 막혀도 503 완료, 늦게 실행된 재개의 DB 작업 생략, 사용자 ID 전달.
- `PlaceListSnapshotCatchUpIT`: 실제 MySQL 공유 발행물 복원과 MockMvc asyncDispatch·Security·예외 응답을 함께 검증한다. 적재가 늦은 인스턴스에서 같은 커서로 조회를 이어가는 경로와 첫 페이지 복원을 포함한다.
- 삭제 장소의 표시값이 발행 payload와 복원 홀더에 남지 않는 회귀를 추가했다.
- 기존 테스트의 빈 대조군, 두 번째 노드 태그 미비교, deadlock 카운터 조회 실패의 묵시적 통과, 실제 동작과 반대인 이름, 스케줄러 실행 시점에 의존한 락 행 단언을 보완했다.

## 범위와 한계

실제 MySQL을 사용하며 H2나 같은 트랜잭션의 순차 호출로 경쟁 검증을 대체하지 않는다. 새 통합 테스트의 초기 실패는 MockMvc 중복 파라미터와 응답 문자열 인코딩을 수정한 뒤 해결했으며, 최종 전체 실행에는 실패나 skip이 없다.

이 검증은 기능과 경쟁 조건의 회귀를 확인한다. 운영 트래픽에서의 p95, CPU·힙 여유, 첫 페이지의 추가 DB 조회 비용이나 대규모 동시 대기 큐의 용량을 보장하지 않는다. 2초 설정은 적재와 재개 큐의 대기 예산이며 초기 동기 처리·이미 시작한 재조회·네트워크 시간을 포함한 HTTP 전체 지연 상한은 아니다.

동시 다운로드 횟수는 실제 DB를 연결한 조정자 직접 호출로 검증하며, 동시 HTTP 요청 두 개를 통한 부하 검증은 아니다. IT의 대기 설정은 1500ms이고 운영 기본값은 2000ms다. 일부 시간 단언은 느린 실행 환경에서 영향을 받을 수 있다. 관리자 직접 설치와 공유 적재의 중복 다운로드는 이번 검증에서 별도로 다루지 않는다.
