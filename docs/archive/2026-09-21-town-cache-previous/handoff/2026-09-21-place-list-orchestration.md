## 역할과 실행

- 당신은 새 메인 코디네이터다. 구현과 테스트는 **Claude Opus5 세션**에 맡기고, 최종 계약/diff/증거는 직접 검토한다.
- Orca `orchestration`/`orca-cli` 스킬의 실제 가이드는 `orca skills get ...`로 읽는다. 메인 모델은 사용자 기본값, 작업자는 `--agent claude --model claude-opus-5` 사용. 요청값뿐 아니라 실행 receipt의 effective 모델을 확인한다.
- 기존 Run을 무단 인계받지 말고 새 Run을 생성한다. 이전 Run은 사전 조사용 `run_2018a49e4308`이며 현재 메인이 settlement/cleanup 후 인계한다.
- 현재 checkout은 `/Users/mkyu/Desktop/SOPT/solply-server`, 기준 `develop@64a97e08274303199b33244ba579adde22e4437d`. 실제 상태를 재확인한다. 원본의 local ignored 설정과 문서 변경을 보존한다.
- 구현은 develop 위에서 바로 덮어쓰지 말고 충돌 없는 작업 브랜치/Orca worktree를 마련한다. 읽기 전용 사전 조사는 현재 checkout에서 수행했다.
- 여러 구현자가 같은 파일을 동시에 편집하지 않도록 소유권을 정한다. 이 작업은 공통 계약이 크므로 무리하게 병렬 분할하지 않는다.
- 현재 범위는 비교 구현·검증·기록. PR/배포를 임의 진행하지 않는다.

1. 최종 설계와 사전 조사 보고서를 검토하고 구체적 파일/인터페이스/테스트/실험 계획을 작성한다.
2. Opus5 구현 작업을 배치한다. 동네 버전 계약을 먼저 고정하고, 정적 5축만 비교한다.
3. 기능/DB 동시성 검증을 통과한 후보만 성능 비교한다. 기존 CPU/JIT 분석은 참고하되 대체하지 않는다.
4. 사전정렬을 채택하기 위해 유리한 시나리오만 고르지 않는다. 이득이 없으면 더 단순한 대안을 선택한다.
5. 요구사항·트레이드오프·최종 근거를 작업 종료 문서에 연결한다. 사용자가 가장 중요하게 지정한 산출물이다.
