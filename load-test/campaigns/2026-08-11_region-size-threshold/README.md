# 2026-08-11 · 지역 크기 축 임계 스윕 (전환 비율 규명)

> 이슈 [#385](https://github.com/SOLPLY/SOLPLY-SERVER/issues/385) 후속 · **부하 아님 — 실행계획 채취.**
> 아래 다섯 항목은 **측정 전에 등록**했다 (2026-08-11, 사용자 확인 완료).
> 판정은 시간이 아니라 **플랜 형상(드라이빙 테이블 + Sort/Materialize 유무)** 우선,
> 우열은 `EXPLAIN ANALYZE` 3회 중앙값 — 경계 칸은 2배 미만 차이가 예상되므로 시간을
> 점이 아니라 **구간으로만** 말한다 (가이드 A.1).

## 1. 문제

판단 규칙의 임계 1,000(`PlaceListJoinOrderPolicy.MIN_EFFECTIVE_TAG_PLACES`)은 지역 후보
1,800 한 점의 실측에서 나온 상수다. 전환점을 실제로 지배하는 변수는 비율(유효 태그 규모 ÷
지역 후보 수, 1,800 기준 0.4~0.64)로 추정되지만, 지역 크기를 한 점에서만 쟀기 때문에
규칙이 분모(지역 후보 수)를 읽지 못한다. 복수 동네 조회의 후보 수가 1,800과 크게
달라지면 — 특히 커지면 — 임계의 전제가 깨진다.

## 2. 원인 가설

태그 주도 계획의 비용은 전국 태그 엔트리 수 N에 비례하고(엔트리 전수 탐색 + 조인),
지역 주도 계획의 비용은 지역 후보 수 R에 지배된다(후보 정렬 + LIMIT 조기 종료 프로브).
따라서 실측상 옳은 전환점 N\*는 R에 대략 비례하고, **전환 비율 N\*/R은 R과 무관하게
일정할 것이다** (1,800 실측: 인기순 0.39~0.64, 최신순 0.22~0.39).

## 3. 기술적 선택

비례가 확인되면: 동네별 장소 수 캐시(`PlaceTagCountCache`와 같은 패턴)를 추가하고 판단
규칙을 "유효 태그 규모 ÷ 요청 동네들의 장소 수 합 ≥ 측정 비율(보수 마진 포함)"로 전환한다.
이 캠페인은 그 전환의 근거를 만드는 **규명 측정**이다 — 비례 확인·기각 둘 다 유효한
결과이고, 결론을 정해 놓고 재지 않는다.

## 4. 검증할 주장

지역 후보 수 6점 — **300 / 600 / 1,000 / 1,800 / 3,600 / 6,000** (100곳짜리 동네
301~360을 3 / 6 / 10 / 18 / 36 / 60개 조합; 1,800은 기존 시 단위와 동일 구성) — 에서
각각 태그 규모를 **비율 격자 {0.15, 0.22, 0.30, 0.40, 0.52, 0.64, 0.80} × R**
(R ≤ 1,000에는 1.0 추가)로 스윕하면:

- 자연 vs 강제(`JOIN_PREFIX`)의 우열이 뒤집히는 **전환 구간을 지역 크기별로 특정**할 수 있고,
- 그 구간을 비율로 환산해 지역 크기 간 비교가 가능하다.

합성 태그는 직전 캠페인과 같은 방식(전국 균등, Bresenham 등간격, id 9001~)으로 깔고,
같은 크기는 태그 하나로 공유한다. 셀 수: 45개 (R, 비율) 조합 × 정렬 2 × 형태 2 =
**180칸**, 칸당 워밍업 1회 + `EXPLAIN ANALYZE` 3회 (경계 의심 칸은 7회 재채취 허용).
태그는 단일 EXISTS라 옵션군 구체화 문제가 없다 — 힌트는 `JOIN_PREFIX` 단독
(직전 캠페인 단일 태그 칸과 동일 형태).

## 5. 성공 조건 (갈림길 사전 등록)

- **(a) 비례 성립**: 전환 비율 구간이 6개 지역 크기에서 겹치거나 좁은 대역에 들어온다 →
  비율 규칙 전환의 근거 성립. 임계 비율 = 구간 합집합의 상단 + 보수 마진
  (기존 임계와 같은 방향 — 이득 최대 1.8배 vs 손해 최대 42.6배의 비대칭).
- **(b) 비례 기각**: 전환 비율이 지역 크기에 따라 단조 이동해 대역이 겹치지 않는다 →
  상수 규칙 유지, **구현 없이 규명 기록으로 종결**.
- 자연 형태가 이미 지역 주도인 칸은 "옵티마이저가 스스로 전환한 지점"으로 따로 기록한다.

## 결과

180칸을 채취하고 경계 의심 48칸(24개 정렬·R·비율 조합)을 7회로 다시 쟀다. 전환 구간은
**지역 크기별로 특정됐다**(주장 ①·② 충족) — 최신순은 6점 전부, 인기순은 R=300(격자 안에 전환
없음)과 R=6,000(자연이 먼저 지역 주도로 넘어가 판별 불가)을 뺀 4점이다.

**그러나 원인 가설은 반증됐다. 사전 등록한 갈림길 (b) 발동.** 전환 비율이 지역 크기를 따라
단조로 내려간다 — 최신순 0.80~1.00 → 0.52~0.64 → 0.40~0.52 → 0.30~0.40 → 0.22~0.30 →
0.22~0.30으로, 양 끝 대역이 3배 이상 어긋나 겹치지 않는다(인기순도 같은 방향). 절대 전환점
N\*로 바꿔도 R에 비례하지 않는다(R 20배에 N\* 5.8배). 원인은 비율 가설이 깔았던 암묵 전제가
틀렸기 때문이다 — 태그 주도 계획의 비용도 R에 의존한다(지역 필터 생존자 ≈ N×R/6,320이 정렬·반출로
넘어간다). 두 계획이 모두 R에 의존하고 차수가 다르니 전환점이 R에 정비례할 수 없다.

따라서 **비율 규칙(N/R ≥ c)은 상수 규칙보다 나은 근사가 아니고**, 등록한 대로 상수 규칙
(`MIN_EFFECTIVE_TAG_PLACES = 1,000`)을 유지하며 **구현 없이 규명 기록으로 종결한다.**
동네별 장소 수 캐시는 만들지 않는다.

**부수 발견 — 상수 규칙의 위험 지대가 실측됐다.** 전국급 지역 후보(R=6,000)의 인기순 발동 셀에서
강제가 최대 **2.01배 손해**(N=1,320: 자연 1.70 vs 강제 3.42ms), N=1,800도 1.33배 손해다.
최신순은 같은 R에서도 안전하다. 다만 현행 복수 동네 조회는 시 단위 18곳(후보 ≈1,800)이고
동네 36~60곳을 한 요청에 담는 경로가 없어, 이 손해는 "그런 요청 형상이 생기면"의 조건부다.
직전 캠페인 문서 §7의 "1,800보다 커지는 쪽이 재측정 조건"이 실측으로 확인됐고, 손해의 크기가
절벽(42.6배)이 아니라 2배 규모라는 것도 이번에 알게 됐다.
