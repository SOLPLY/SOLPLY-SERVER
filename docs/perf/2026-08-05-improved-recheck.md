## 4. 500의 p50 하위 조건 — 왜 반쪽인가

r2는 4/4 충족(p50 10.1ms ≤ 18ms), r3은 p50만 미충족(53ms). r3의 서명이 명확하다:
처리량·실패·SQL/요청·행 읽기가 r2와 전부 동일한데 **요청당 CPU만 앱 +9%·DB +7%** — 같은
일에 CPU를 더 쓴 것은 호스트 경합의 서명이다(코드가 원인이면 원인 지표가 함께 움직여야 한다).
호스트 로드가 라운드 내내 단조 상승(3.96 → 10.11)했고 배경 프로세스가 상시 점유 중이었다.

판정은 통과로 하되 **p50 절대값은 등록대로 "기록만"이다.** 하위 조건의 완전한 재확인이
필요하면 깨끗한 호스트에서 500 1라운드로 충분하다.

## 5. 650 관찰 — 다음 천장은 앱이다

- 500에서 비등하던 앱·MySQL 스로틀(≈29% vs 27%)이 650에서 **52~59% vs 23%로 갈라졌다.**
  MySQL은 사용률 59%·스로틀 23%로 500 지점과 거의 같다 — **DB는 여유를 남기고 앱이 무너졌다.**
  등록서 §2의 예고(직전 캠페인 500B에서 앱 스로틀 45.7~48.2% 관찰)가 그대로 실현된 형태.
- 실패의 상당수는 LB 서킷브레이커 산물: 앱 응답 지연 → `proxy_connect_timeout 5s` 초과 →
  `max_fails=3`으로 두 upstream 동시 차단 → `no live upstreams` 502 즉답(31,562건).
  `worker_connections` 경고 0 — LB 자체는 견뎠다. 즉 650의 실패율은 순수 적체보다
  붕괴를 급격해 보이게 하는 왜곡이 섞여 있다.
- 앱 메모리 786~879MiB → 1,170~1,403MiB (적체 힙 압력). 앱 예외 로그는 0건.

## 6. 부수 확정 — 배치 스케줄 상충 해소

cron은 `0 30 * * * *`(**매시 :30**)로 확정, 이번 실측 발화도 01:30:04 (전 라운드 종료 후,
겹침 0건). 직전 캠페인의 ":00 부근 발화" 관찰(amp §9-1)은 `calculated_at`(집계 기준 시각 —
정시 상한 컷오프)을 발화 시각으로 읽은 오독으로 보인다(가설 — 컷오프 로직은 배치 코드에서
확인 가능). **측정 회피창 규칙은 ":30 부근"으로 유지한다.**

## 7. 유효성 특이사항

1. **호스트 오염이 상시 존재**(배경 앱 다수, 로드 단조 상승) — r3 오염 서명은 §4. 순간 급등
   무효 규칙으로는 안 걸리는 지속 경합이라, p50 계열은 전부 참고로 강등.
2. 300-r1 워밍업 폐기 타당성 재확인(앱 스로틀 14.6% vs r2 4.8%).
3. docker stats 상한 초과 재현(앱 343% / 상한 200%) — 판정은 전부 cgroup.
4. LB 컨테이너는 재생성하지 않아 로그에 이전 캠페인 분이 누적돼 있고 **nginx 로그는 UTC**다.
5. HikariCP `threads_connected` 21 고정 — 커넥션 고갈 없음.

## 8. 이 테스트로 말할 수 없는 것

1. **p50·p95의 절대값과 개선 폭** — 호스트 경합 미통제. 구조 지표만 주장한다.
2. **새 천장의 정밀 위치** — 시도 600(통과)과 700(붕괴) 사이, 협착하지 않았다.
3. **650 수치의 판정력** — 관찰 2라운드 + 호스트 오염 + LB 서킷브레이커 왜곡.
4. **앱 CPU의 용처** — 프로파일링 없음. "앱이 병목"까지만 말할 수 있고 "무엇에 쓰는지"는 다음 질문.
5. **개별 개선의 기여 분해** — 단일 형상 측정이라 STRAIGHT_JOIN vs SQL 다이어트의 몫을 못 가른다.
6. **쓰기 혼합 믹스의 거동** — 읽기 전용 한정.

## 9. 후속

1. **앱 CPU 프로파일링** — 새 천장의 병목 정체(직렬화? JWT 파싱? GC?) 규명. 다음 개선의 표적.
2. **②b 세대 키 로컬 캐시** — DB SQL 제거와 앱 작업 절감을 동시에 건드리는 후보.
   우선순위는 1의 결과와 함께 판단.
3. (선택) 깨끗한 호스트에서 500 1라운드 — p50 하위 조건 완전 재확인.
4. 벤치 LB 서킷브레이커 파라미터 재검토 — 포화 모양 왜곡(§5) 완화용, 벤치 한정.
