# 2026-08-11 · 조인 순서 전환점 탐색 (임계 탐색)

> 이슈 [#385](https://github.com/SOLPLY/SOLPLY-SERVER/issues/385) · **부하 아님 — 실행계획 채취.**
> 아래 다섯 항목은 **측정 전에 등록**했다 (2026-08-11, 사용자 확인 완료).
> 판정은 시간이 아니라 **플랜 형상(드라이빙 테이블 + Sort 노드 유무)**으로 한다 —
> 경계 근처는 2배 미만 차이가 예상되므로 시간은 기록만 한다 (가이드 A.1).

## 1. 문제

시 단위 + 태그 조회에서 옵티마이저가 태그 주도 계획을 고르는데, `JOIN_PREFIX(ps)`로 지역
주도를 강제하면 3배 빠르다 (인기순 서울 + 태그 3개 2.45 → 0.81ms,
`2026-08-10_join-order-hint-recheck`). 조건부 힌트를 구현하려면 "태그 카디널리티가 얼마일 때
지역 주도가 옳은가"의 경계가 필요한데, 지금 있는 것은 두 지점뿐이다 — 185곳(지역이 옳은데
V33 후 태그로 뒤집혀 2배 손해), 1,146곳(태그 주도 선택, 강제가 3배 이득). 선이 없다.

## 2. 원인 가설

코스트 모델이 정렬 인덱스의 스트리밍 실행 + LIMIT 조기 종료 이득을 반영하지 못한다
(지역 주도를 추정 비용 2.2배 비싸다고 보지만 실측 3배 빠름). 따라서 옵티마이저의 드라이빙
전환점은 실측상 옳은 전환점보다 태그 주도 쪽으로 치우쳐 있을 것이다.

## 3. 기술적 선택

캐시된 태그 실카운트를 입력으로, 실측 경계 안쪽 요청에만 `JOIN_PREFIX(ps)`를 붙이는
조건부 힌트 (#385). 이 캠페인은 그 경계를 정하는 규명 측정이다.

## 4. 검증할 주장 (규명 — 채택/기각 없음)

- ① 태그 규모 스윕(20 / 50 / 100 / 185 / 400 / 700 / 1,146곳) × 지역(동네 100 / 시 1,800) ×
  정렬 2에서, **옵티마이저가 드라이빙을 태그→지역으로 바꾸는 지점**과 **실측상 바꾸는 것이
  유리한 지점**을 각각 특정할 수 있다
- ② 복수 태그(메인 + 희귀 서브태그) 요청에서 태그 주도 플랜의 드라이빙이 무엇인지 —
  메인 태그 고정인지, 최소 카디널리티 태그인지 — 트리로 확인된다
- ③ 각 스윕 지점의 `JOIN_PREFIX(ps)` 강제 실측값을 확보한다 (구현 후 검증의 지점별 기준값)

## 5. 성공 조건

채택/기각이 아니라 지도의 완성: (a) 전환 경계가 지역·정렬별로 특정되고 (b) 판단 규칙의
비교식(태그 카운트 vs 지역 카운트)으로 번역 가능하면 성공. **두 전환점이 거의 일치하면
(어긋난 구간이 무시할 크기) 조건부 힌트 구현을 중단하고 규명 기록으로 종결한다** —
사전 등록된 갈림길.

## 검증 환경

| 항목 | 값 |
|---|---|
| 토폴로지 | `docker/docker-compose.bench.yml` — MySQL(2 CPU / 3G, 버퍼풀 2G) 단독. **앱 정지** |
| 스키마 | **V32 + V33** (place_stats 단일행 · place_tag `(tag_id, place_id)` 커버링) |
| 데이터 | 활성 장소 6,320 · `place_tag` 15,461 + 합성 태그 · `tags` 34행 + 합성 |
| SQL | 현행 `PlaceListDbQueryRepository`의 인기순·최신순 (`tags` 조인 없는 상태) |
| 시간 값 | `EXPLAIN ANALYZE` 최상위 노드 actual time **3회 중앙값** |

합성 태그는 규모별로 **전국 균등 분포**로 깐다 (실태그의 지리 분포는 재현하지 않음 —
한계로 명시). 시딩·형상 전환마다 `ANALYZE TABLE`로 통계를 대칭으로 맞추고, 채취가 끝나면
합성 태그를 롤백한다. **제품 코드·마이그레이션은 건드리지 않는다.**

## 결과

96칸을 채취했다. **주장 ①은 부분 충족** — 시 단위에서는 태그가 지역 후보 1,800의 64%(1,146곳)까지
커져도 옵티마이저가 태그 주도를 놓지 않아 전환점이 스윕 밖이고, 실측상 옳은 전환은 인기순
700~1,146 · 최신순 400~700 사이다(동네 1곳은 전환점이 스윕 안에 있으나 자연·강제 차이가 최대
0.094ms라 판단 대상이 아니다). **주장 ②는 충족** — 복수 태그의 드라이빙은 메인 고정이 아니라 언제나
일치 행 수가 가장 작은 그룹이고, 이것이 판단 규칙의 "AND 그룹별 합의 최솟값"을 정했다.
**주장 ③은 충족이면서 추가 발견을 냈다** — 실태그 3조각 조합에서 `JOIN_PREFIX` 단독은 옵션군
`EXISTS`가 구체화로 바뀌어 이득이 사라지고(7회 중앙값 2.12 vs 자연 1.99), `SEMIJOIN(FIRSTMATCH)`를
함께 걸어야 1.03 / 0.889ms가 된다. 힌트는 조인 순서만 고정하고 세미 조인 전략은 고정하지 않는다.
사전 등록한 갈림길(두 전환점이 거의 일치하면 종결)은 발동하지 않아, 판단 규칙(복수 동네 + 태그 존재
+ 그룹별 합의 최솟값 ≥ 1,000)과 조건부 힌트를 구현·채택했다(커밋 `f03c91b`).
