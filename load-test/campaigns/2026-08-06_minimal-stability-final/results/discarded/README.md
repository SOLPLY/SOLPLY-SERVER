# 폐기한 시도 — `r-c-ABORTED-04-43`

**폐기 사유: 부하 생성기가 측정 중 정지당했다. 서버 문제가 아니다.**

라운드 C를 정확한 시각(`xx:28:50`)에 시작시키려고 대기 루프를 **백그라운드 프로세스**로 띄웠다.
그 프로세스는 예약 시각(04:28:50)이 아니라 **04:43:23**에 시작했고, 시작한 뒤에도 실행이
간헐적으로 멈췄다. 증거 세 가지:

| 증거 | 값 |
|---|---|
| 도착 | 계획 9,300 중 **4,839 생성** (52%) — 사전 등록 S1(≥99%) 위반 |
| 응답시간 | median **2,725ms** · p95 4,317ms (같은 부하의 정상 라운드는 median 5ms) |
| 서버 자원 | 같은 구간 앱 CPU **40%대**, MySQL 30%대 — 서버는 놀고 있었다 |
| 샘플러 | 140초 예약인데 04:44:21에 멈춤 (프로세스가 정지당한 흔적) |

서버가 느렸다면 자원 지표가 올라갔어야 한다. 올라가지 않았으므로 **부하 생성기 쪽 정지**다.
가이드 §6의 "오염 구간만 잘라내지 않는다"에 따라 **라운드 전체를 폐기**하고, 재실행은
백그라운드 없이 전경(foreground)에서 수행했다 (`r-c-120-batch`).

원자료는 이 디렉터리에 그대로 남긴다 — "왜 다시 측정했는가"를 지우지 않기 위해서다.
숫자는 **어떤 판정에도 인용하지 않는다.**
