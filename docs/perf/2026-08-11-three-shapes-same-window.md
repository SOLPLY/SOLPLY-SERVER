# 같은 창 세 구조 비교 — 조인 구조만 바꿔 각 솔루션의 몫을 분리한다

캠페인: [`load-test/campaigns/2026-08-11_three-shapes-same-window/`](../../load-test/campaigns/2026-08-11_three-shapes-same-window/)
> 이슈 [#385](https://github.com/SOLPLY/SOLPLY-SERVER/issues/385) 후속 · **부하 아님 — 실행계획 비교.**
> 블로그 원고([태그 필터 조회](../blog/2026-08-11-tag-filter-join-order.md))가 인용하는
> 개선 수치의 정본이다.

## 1. 왜 다시 쟀는가 — 창과 기반을 통일하기 위해

기존 사다리는 "처음 구조 수치(08-06, V31 기반) → 조인 제거·읽기 모델(08-11, V33 기반)"로,
두 가지가 섞여 있었다.

- **기반 차이**: V32(place_stats 단일행)·V33(place_tag 커버링)은 조인 구조와 무관한 기반
  개선인데, 날짜가 다른 측정을 이으면 이 개선분이 조인 구조의 몫에 섞인다.
- **창 차이**: 같은 쿼리·같은 계획도 캐시·통계 상태에 따라 값이 달라진다. 이번 캠페인의
  재현성 확인에서 하루 차이로 3.1배 다른 칸(조인 제거·시 18곳·다중 그룹 인기순: 2.05 vs
  6.44ms)이 실측됐다. 날짜를 건너뛰는 절대값 비교는 이 폭만큼 흔들린다.

그래서 **기반을 현행(V32+V33)으로 고정하고, 쿼리 구조만 세 가지로 바꿔 한 창에서 쟀다.**

| 열 | 형상 | 쿼리 |
|---|---|---|
| JOIN | V34 롤백 (V32+V33) | 당시 구조 — 그룹당 EXISTS + IN 목록, EXISTS 안에 `tags` 조인(`t.active=1`) |
| A | 동일 | 조인 제거 — `tags` 없는 EXISTS, 자연 계획(힌트 없음) |
| B | V34 적용 | 읽기 모델 — `place_stats` 단독 + 그룹 마스크 술어 |

이 설계에서 JOIN→A 배수는 온전히 "`tags` 조인 제거가 해결한 것", A→B 배수는 온전히
"읽기 모델이 해결한 것"이 된다. 당시 스키마(V29 세대 행)까지 되살리는 안은 쓰지 않았다 —
비교 목적이 "과거 재현"이 아니라 "솔루션별 몫의 분리"이기 때문이다.

측정: 그리드 42칸(지역 3 × 태그 7 × 정렬 2) + 다중 그룹 칸의 커서 2페이지. 칸마다
`EXPLAIN ANALYZE` 워밍업 1회 + 3회 중앙값(무거운 칸 7회). 합성 태그(규모 20 id 40 ·
0건 id 41)는 채취 전 시드, 후 롤백(잔재 0 확인). 술어는 전 열이 확정 스펙
(그룹 내 OR + 그룹 간 AND, 메인 단일)이다.

## 3. 확인 ① — 오추정 형태는 다중 그룹 칸에서만 생긴다

**의도:** 원인 진단("IN 목록이 `tags`를 계획에 남겨 오추정을 만든다")이 맞다면, `tags`
노드·카테시안 결합은 다중 그룹 칸에만 나타나고 단일 태그 칸에는 없어야 한다.

**결과:** 트리 전수 확인으로 성립. `tags` 노드는 다중 그룹 6칸에서만 2개씩 나타났고
(나머지 36칸은 0개 — `t.id = 상수`가 계획 수립 전에 접힘), 그중 5칸에서 카테시안 결합 +
추정 오차(실제/추정 17~70배: 예 추정 0.67 vs 실제 41) + 계획 뒤집힘(`tags` 6행에서 출발해
전국 엔트리 1만여 개 + 중복 제거)이 재현됐다. 그 5칸이 11.7~22.9ms의 전부다.

동네 1곳 인기순 다중 그룹 1칸은 이 창에서 뒤집히지 않았다(0.339ms, 지역 출발). 두 계획의
비용이 붙어 있는 경계 칸으로, [08-06 창](2026-08-06-tag-filter-join-order.md)에서는 잘못된
쪽이 선택돼 11.3ms였다. 참사 재현 여부 자체가 측정 창의 캐시 상태에 좌우된다.

## 4. 확인 ② — 조인 제거의 몫은 오추정 칸에 국한된다

**의도:** JOIN→A가 "틀린 계획을 고르게 만들던 정보의 제거"라면, 개선은 오추정이 판단을
좌우하던 칸에만 나타나고 나머지는 무변화여야 한다.

**결과:** 성립. 오추정 칸에서 3.6배(시 인기)~49배(동네 1곳 최신), **나머지 36칸은
0.56~1.6배로 무차이.** 단일 태그 칸의 계획은 JOIN과 A가 사실상 동일했다.

## 5. 확인 ③ — 읽기 모델은 계획을 하나로 만들고, 조인 제거가 못 고친 칸을 고친다

**의도:** ①형태 단일성(어떤 입력도 계획을 못 바꿈 — 한 칸이라도 갈리면 채택 반증) ②남은
흔들림 칸(단일 태그 태그 출발, 정렬 축 뒤집힘)의 해소.

**결과:** ① 42칸 + 커서 2페이지 전부 `ps` 지역 출발 한 형태(조인 노드 0). JOIN/A가
`ps`/`p`/`pt`/`t` 네 가지를 오가는 동안 B는 무엇으로도 형태가 갈리지 않았다. ② 시 카페
최신순 1.79 → 0.770(2.3배), 동네 4곳 이색공간 최신순 1.36 → 0.192(7.1배), 다중 그룹 시
단위 6.44/2.89 → 0.757/0.677(8.5/4.3배). 시간 대역은 지역당 하나로 수렴 — 동네 1곳
0.03~0.07 / 동네 4곳 0.16~0.23 / 시 0.57~0.87ms.

## 6. 확인 ④ — 수용한 후퇴의 절대 상한

**의도:** 태그 출발 지름길을 잃은 희귀·0건 태그가 사전 등록 상한(시 단위 ≤ 2ms) 안인가.

**결과:** 성립. 합성 20: 0.081 → 0.681ms(8.4배 후퇴) · 0건: 0.015 → 0.760ms(51배 후퇴).
절대값 최악 0.76ms로 상한 안. 최악이 입력이 아니라 지역 후보 수에 묶였다.

## 7. 이 캠페인으로 말할 수 없는 것

- **당시(V31 기반) 사용자가 겪던 절대값** — JOIN 열은 기반을 현행으로 고정한 값이라 당시
  기록(08-06)과 절대값이 다르다. 개선 주장의 수치는 이 캠페인, 당시의 역사는 08-06 문서가
  각각 담당한다. 두 캠페인의 절대값을 한 사다리에 섞지 않는다.
- **경계 칸의 재현성** — 동네 1곳 인기순 다중 그룹은 창에 따라 계획이 갈린다. 이 창의
  0.339ms는 "그날은 사고가 안 났다"이지 "사고가 없다"가 아니다.
- 실태그의 지리 편중(합성 태그는 전국 균등), 부하 하의 거동(부하 0), 태그별 요청 빈도
  분포(미측정)는 기존 캠페인과 같은 한계다.
