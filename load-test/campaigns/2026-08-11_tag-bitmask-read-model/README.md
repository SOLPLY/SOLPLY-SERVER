# 2026-08-11 · 태그 비트마스크 읽기 모델 전환 (A/B 실행계획 비교)

> 이슈 [#385](https://github.com/SOLPLY/SOLPLY-SERVER/issues/385) 후속 · **부하 아님 — 실행계획 전후 비교.**
> 아래 다섯 항목과 시나리오별 판정 목적은 **측정 전에 등록**했다 (2026-08-11, 사용자 확인 완료).
> 판정은 **플랜 형상 우선**(조인 노드·세미조인 노드의 존재 여부, 조기 종료 위치), 시간은
> `EXPLAIN ANALYZE` 3회 중앙값(경계 칸 7회 허용). 2배 미만 차이가 예상되는 칸(S3)은 시간을
> 보조 근거로만 쓴다.

## 1. 문제

태그 필터 목록 조회의 실행 계획이 입력(태그 규모 × 지역 크기)에 따라 태그 주도와 지역 주도
사이에서 흔들리고, 옵티마이저는 LIMIT 조기 종료를 비용에 세지 못해 흔한 태그 + 넓은 지역에서
틀린 계획을 고른다. 조건부 힌트(`JOIN_PREFIX`+`SEMIJOIN(FIRSTMATCH)`, 임계 1,000)는 그 맹점을
우회하지만, 임계가 "지역 후보 ≈1,800" 한 형상에서만 유효함이 확정됐고(전환 비율이 지역 크기에
단조 하강 — `2026-08-11_region-size-threshold`), 카운트 캐시 + 힌트 두 벌 + 판단 정책이 읽기
경로의 상시 부채로 남는다. **조건부 힌트는 복잡도 대비 이점 부족으로 철회한다.**

## 2. 원인 가설

문제의 뿌리는 `place_tag` 조인 자체다. 조인이 존재하는 한 옵티마이저에게 조인 순서·세미조인
전략의 자유도가 있고, 그 선택이 비용 모델의 맹점에 노출된다. 수치: 시 단위 실태그 3조합에서
자연 1.99ms vs 지역 주도 강제 1.03ms(인기순), 반대로 희귀 태그(규모 20)에 강제 시 42.6배 손해
— 개입의 정오가 입력에 좌우되고, 개입 규칙의 유효 범위는 요청 형상 한 점에 묶인다.

## 3. 기술적 선택

`place_stats`를 두 정렬의 단일 읽기 모델로 완성한다.

- `created_at`·`tag_bitmask`(BIGINT, 비트 자리 = tag id) 컬럼 추가, 커버링 인덱스 2개
  (인기순 기존 말단 확장 + 최신순 `(town_id, created_at, place_id, ...)` 신설 — PK가
  `place_id`라 역방향 스캔이 커서 타이브레이크와 일치)
- EXISTS 3개 → 그룹 마스크 술어 3개(`(bm & :mask) != 0`, 메인 AND 옵션A-OR AND 옵션B-OR
  의미론 유지), 최신순의 `places` 기준·LEFT JOIN 제거
- 정합: 어드민 생성·수정·재활성이 같은 트랜잭션에서 ps 행·마스크를 동기 유지 + 매시 카운트
  배치가 재계산(드리프트 수명 ≤1h) + 태그 생성 시 비트 자리 62 초과 거부 가드
- 조건부 힌트 일습(`PlaceListJoinOrderPolicy`·`PlaceTagCountCache`·힌트 조립부) 전부 삭제

수용한 대가(사전 합의): 희귀·0건 태그가 태그 주도 경로를 잃고 지역 스캔이 된다(S2로 상한 판정).
어드민 우회 비활성화가 최신순에 ≤1h 잔존한다(인기순은 이미 같은 계약).

## 4. 검증할 주장

**A = 현행 스키마 + 자연 플랜**(조인 제거 후 옵티마이저 선택 — 힌트 철회 상태의 SQL과 바이트
동일). **B = 마이그레이션 + 마스크 술어.** A를 마이그레이션 적용 **전에** 선채취한다 — 컬럼·인덱스
추가가 A의 플랜에 영향을 줄 수 있는 상태에서 재면 비교가 오염된다. 힌트 실측치(1.03/0.889ms)는
재측정하지 않고 `2026-08-11_join-order-threshold`의 기록을 참조점으로만 쓴다.

- ① 모든 칸에서 B의 실행 트리가 단일 형태다 — ps 커버링 스캔 + 비트 필터, 조인 노드 0,
  세미조인 노드 0. 태그 규모·지역 크기가 플랜 형태를 바꾸지 못한다
- ② 동네 1곳은 조기 종료가 유지된다 — 트리에서 11건 언저리 멈춤
- ③ 시 단위 + 흔한 태그는 힌트 없이 힌트 실측치 이상이다
- ④ 희귀·0건 태그의 후퇴는 "지역 커버링 엔트리 전수 스캔"이 상한인 결정론적 비용이다
- ⑤ 결과 집합이 불변이다 — 마스크 술어 ↔ EXISTS 동치 (IT 담당)

### 그리드

```text
지역 3   동네 1곳 town_id 301(후보 100) · 동네 4곳 301~304(400) · 시 단위 18곳 301~318(1,800)
         — 벤치 DB의 동네 301~360은 정확히 100곳씩이라 곳수 × 100이 후보 수다
태그 7   무태그 · 흔한 메인(카페 id 1, 1,146) · 흔한 메인+서브 2그룹(핫패스 — 카페 id 1 +
         OPTION1 (7,8,9,10) + OPTION2 (11,12,13,14,15,16)) · 비인기 메인(**이색공간 id 5,
         985** — 벤치 DB의 PLACE MAIN 6개 중 최소. 985/992/1,045/1,058/1,094/1,146으로
         실태그 MAIN은 규모가 촘촘해 "비인기"라 해도 카페의 86% 수준이다) ·
         메인+희귀 서브(음식 id 2 + 바/술집 id 21, min그룹 185) · 합성 규모 20(id 40) ·
         0건(id 41)
정렬 2   인기순 · 최신순
커서     1페이지 전 칸 + 2페이지는 핫패스 칸(흔한 메인+서브)만 — 직전 캠페인의 미측정 구멍
         (단 동네 1곳 핫패스는 매치가 10건뿐이라 2페이지가 존재하지 않는다 — 측정 시 확인,
          A·B 양쪽에서 같은 이유로 빠진다)
```

전국급(후보 6,000)은 **측정하지 않는다** — 서비스가 만들 수 없는 요청 형상이다(조회 상한 = 시 단위).

합성 태그는 **id 40(규모 20, 전국 균등) · id 41(0건, place_tag 연결 없음)**을 쓴다. 직전
캠페인의 id 9001~ 규약을 따르지 않는 이유: B의 비트 자리 = tag id라 62 이하여야 하고, A·B가
같은 태그를 써야 비교가 성립한다. A 채취 후 유지, B 채취 후 롤백(잔재 0 확인).

### 시나리오별 판정 목적 (사전 등록)

| 칸 | 무엇을 확인하는가 | A 예상 | B 예상 | 판정 |
|---|---|---|---|---|
| 무태그 | 마이그레이션 무해성 — 인덱스 엔트리 폭 확장이 최다 트래픽 경로를 건드리지 않는가 | 기존 플랜 | 플랜 노드 동일 + 시간 동등 | S5 |
| 흔한 메인 단독 | A의 맹점 재현(시 단위 태그 주도) vs B의 형태 고정 | 시 단위 태그 주도 / 동네 지역 주도 | 전 지역 동일 형태 | ①·S4 |
| 흔한 메인+서브 2그룹 | **핫패스·S3 기준 칸.** 세미조인 선택 문제의 소멸(FirstMatch/구체화 노드 부재) | 1.99 / 2.43ms (시 단위) | ≤ 1.03 / 0.889ms | S3, 커서 2p 포함 |
| 비인기 메인 단독 | 중간 규모에서의 후퇴 폭 — A가 태그 주도로 옳게 처리하는 구간을 B가 얼마나 따라오는가 | 태그 주도 | 지역 스캔 | S2 |
| 메인+희귀 서브 | A가 가장 잘하는 칸(최소 그룹 185부터 탐색)에서의 후퇴 | 태그 주도 ~0.4ms | 지역 스캔 | S2 |
| 합성 규모 20 | B 최악의 극단 — 통과 행이 없어 11건이 안 차고 지역 후보 전수 스캔 | 태그 주도 ~0.05ms | 시 단위 ~1,800 엔트리 스캔 | S2 — 뚫리면 채택 불가 |
| 0건 태그 | 후퇴의 다른 극단 + 결과 0건 동일 | 즉시 종료 | 전수 스캔 후 빈손 | S2 + S1 보조 |

후퇴 칸(하위 4개)의 S2 판정은 시 단위 값으로 한다 — 작은 지역의 통과는 자명하다.

## 5. 성공 조건

- **S1** 결과 불변 — 목록 IT 전부 + 전체 테스트 통과 (마스크 ↔ EXISTS 동치, 커서 케이스 포함)
- **S2** 후퇴 상한 — 시 단위 + {비인기 메인 · 희귀 서브 · 합성 20 · 0건}: 중앙값 **≤ 2ms**
- **S3** 핫패스 — 시 단위 + 흔한 메인+서브: 인기순 **≤ 1.03ms** · 최신순 **≤ 0.889ms**
  (판정은 플랜 형상 ① 우선, 시간은 보조)
- **S4** 동네 1곳 — **≤ 0.2ms** + 트리에서 조기 종료 확인
- **S5** 무태그 — A·B 플랜 노드 동일 + 시간 동등(노이즈 범위)

**반증 시나리오(사전 등록):** ① 위반(어느 칸에서든 B 플랜 형태가 갈라짐) → **채택 자체를 접는다.**
S2 초과 → 후퇴 수용 재협상. S3 미달 → 채택 근거 약화, 원인 규명 후 재판정. S5 위반 → 인덱스
설계 수정 후 재측정.

**트래픽 가중에 대해:** B의 후퇴는 (추정상) 저빈도 입력에 몰리고 개선은 핫패스에 몰린다. 단
태그별 요청 빈도는 미측정이므로 이 비대칭은 채택의 **보조 근거**일 뿐이다 — 채택의 주근거는
"최악이 절대 상한(S2) 안"이라는 실측이다. 장소 수 분포와 요청 빈도 분포는 다른 분포다(장소가
희귀한 태그를 사용자가 자주 고를 수 있다). 운영 지표가 생기면 확인할 항목으로 남긴다.

## 이 캠페인으로 말할 수 없는 것

- 실태그의 지리 편중(합성 태그는 전국 균등 분포)
- 부하 하의 거동 — 부하를 걸지 않는다. 플랜이 단일 형태로 고정되므로 운영에서는 digest
  실행당 지표로 회귀를 감시한다
- 배치·동기 갱신의 정합 — 캠페인이 아니라 IT가 담당한다 (S1)

## 추록 (측정 후)

판정 직후 태그 필터 스펙이 "설정한 태그 전부 포함"으로 확정되어 술어를 단일 마스크
(`(tag_bitmask & :m) = :m`)로 교정했다. 본 그리드의 A·B는 측정 당시 술어(그룹 OR)의 기록으로
보존하고, 교정 술어의 확인 채취는 `bench/explain-b-and-confirm.sh` → `results/summary-b-and.csv`
(14칸: 형태 불변·대역 0.53~0.67ms·기준선 일치·조기 종료 유지)로 별도 기록했다. 판정 갱신은
[결과 문서 §9-1](../../../docs/perf/2026-08-11-tag-bitmask-read-model.md).
